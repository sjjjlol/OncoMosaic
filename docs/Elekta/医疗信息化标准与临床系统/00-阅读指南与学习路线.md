# 医科达软件开发岗｜医学小白速学路线

更新：2026-10-07。适合“会写 Java、做过业务接口，但没接触过医院系统”的候选人。针对 JD 的加分项：了解医疗信息化标准或临床系统，如 DICOM、HL7、FHIR。

## 先确定你要学会什么

你可以把这一项理解成：**知道医疗软件为谁服务、处理什么数据，以及系统之间怎样交换这些数据。**准备到能用具体例子讲明白，再把已有的接口开发、数据库、并发和问题排查经验联系进去。

本套材料围绕一个虚构患者“张明”展开：他到 A 医院登记，医生安排影像检查，相关人员准备并审核放疗计划，之后安排治疗并记录结果。你会看到，每一步都有软件参与，DICOM、HL7 v2、FHIR 就是在这个过程中帮助不同系统沟通。

本文的流程是教学简化示例，方便理解软件职责，不代表某家医院或某个 MOSAIQ 版本的实际流程。标准定义链接放在各章末尾；第一次学习直接按正文读即可。

## 最先掌握这 8 个词

| 词 | 第一次可以这样记 | 张明的故事里对应什么 |
|---|---|---|
| 放疗 | 使用辐射治疗肿瘤的一类方法 | 医生决定安排的治疗 |
| HIS | 医院层面的业务系统 | 登记患者、管理就诊等 |
| PACS | 影像资料的归档与通信系统 | 保存、查找张明的影像 |
| TPS | 治疗计划系统 | 准备放疗计划，评估相关剂量分布 |
| OIS / MOSAIQ | 肿瘤信息与工作流管理 | 将患者资料、计划相关信息、排程与记录联系起来 |
| DICOM | 医学影像及相关数据的交换标准 | 让另一套软件看懂影像和放疗对象 |
| HL7 v2 | 传统医疗系统常见的消息标准 | 通知另一系统“患者登记/信息更新了”等事件 |
| FHIR | 用统一医疗资源模型交换信息的标准 | 通过约定的资源和接口获取患者、预约等信息 |

这是入门记忆方式。准确边界会在正文逐步解释；例如 FHIR 也属于 HL7 标准家族。

## 两小时版与面试前半小时版

**有约两小时：**先读 01 的故事和系统分工，再读三类标准的核心例子，最后在 04 中练习 60 秒回答与三个场景题。遇到“进阶”提示直接跳过，不让细节打断主线。

**只剩半小时：**读 01 的系统分工、02 的消息与 ACK 故事、03 的 Patient 示例，然后练 04 的开场回答和最后一页速记。目标是能举例讲明白，不是把所有缩写念一遍。

## 学会的判定：合上文档回答这五题

1. 张明做了影像检查，PACS、TPS、OIS 分别可能负责什么？
2. 为什么同一患者的影像、计划和治疗记录必须关联正确？
3. DICOM、HL7 v2、FHIR 各用一个例子怎么解释？
4. 消息发送超时为什么不能直接认定处理失败？
5. 两家医院都有编号 P0001，为什么不能直接合并？

能用自己的话讲清楚这五题，就有了继续回答软件场景题的基础。
