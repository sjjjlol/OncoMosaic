# Elekta 二面：简单英文逐题回答

主答案尽量在30–60秒内完成。中文用于理解，英文用于录音。项目过去式只用于已确认经历；假设方案用 would。各题不是已核实真题。

## Q1. Design a set of tests for a simple database interface.

**考点：**先定义契约，再按风险设计测试，不只是 CRUD 成功。

> First, I would **confirm** the **contract of the interface**.
> What should happen if a record is missing or the key already exists?
> I would test **normal reads and writes**, **invalid input**, and **missing records**.
> Then I would test **rollback**, **concurrent updates**, and connection failures.
> For a **versioned update**, two callers can read the same version, but only one should succeed.
> I would run database tests against the actual database engine. A fake is useful for service tests, but it cannot prove database behavior.

**追问：What would you check after a failed write?**

> I would check that **no partial data was saved**. If the result is unknown, I would **check the stored result** before **retrying**.

练习契约、测试矩阵及并发控制见12。

## Q2. Tell me about a challenging project and how you solved its key problems.

**指定主案例：携程合并退款。** 完整故事及追问见11。

> At Ctrip, I worked on **combined refunds for extra products**.
> Each message still carried one refund ID, but the consumer could process a group of records.
> Different messages could lead to different orders for the same group.
> One worker could lock refund 1 first, while another locked refund 2 first. Both could fail to get the remaining lock and return.
> My main fix was to sort the full refund group before taking the first lock.
> Unfinished records could be retried through a scheduled scan. Unsubmitted records past the time limit could use the **single-refund fallback**.
> I learned to check the whole processing flow, not only one task in isolation.

完整流程与“当前＋其他”的具体还原例子见11。**不是上游先合并消息，也不能先锁当前记录后排序。**

若问调查步骤，使用已确认的实际步骤；建议复现与验证用“I would test…”，不要把建议写成经历。

## Q3. What was the biggest failure you had at work?

**按用户指定，使用携程合并退款案例。** 讲“我参与处理的一次系统失败”，不要自动变成“我写错代码导致事故”。如果面试官明确要求本人犯错，必须补真实个人责任，不能杜撰。

### 约60秒回答

> One major failure I helped resolve was in the combined refund flow at Ctrip.
> The consumer had changed from **processing one refund to processing a group**, while **messages were still sent per record**.
> Different workers could take the locks in different orders. **Each could hold some locks and fail to get the rest**, so the refund was not submitted in that attempt.
> My contribution was to make the lock order consistent at the final entry point.
> **I sorted the full group before taking the first lock**. The key rule is not to lock the current record before sorting.
> The lesson for me was to check how different tasks interact, not only whether one task works on its own.

### What would you do differently?

> I would make the lock order part of the contract from the start.
> I would test the group-building path from different current refund IDs, not only pass in sorted lists.
> I would also test scan retries, the single-refund fallback, and overlapping sets.
> Lock expiry and duplicate effects would need separate checks.

这里的would是反思与改进，不声称当时所有测试都已执行。

### Was the original mistake yours?

现有材料没有证实原缺陷归属。不能直接回答yes或no；若本人确实知道，按事实说明。

> My confirmed contribution was investigating the lock order problem and making that order consistent. I would need to check the history before saying who introduced it.

## Q7. Explain OOP. / Some OOPS topics.

OOPS 一般指 OOP 主题，不是另一个独立技术。以下四条可各用一个例子。

| 概念 | 简单英文 | 例子 |
|---|---|---|
| Encapsulation | An object keeps its state and rules together. | Appointment 只有 Confirm/Cancel 能变更状态 |
| Abstraction | An interface shows what a component does and hides how it works. | 调用 store，不让服务关心 SQL 细节 |
| Inheritance | A class can reuse and extend behavior from a base class. | 稳定请求流程的模板方法 |
| Polymorphism | The same interface can have different behavior for different objects. | 两个供应商实现同一个发送接口 |

**选择继承还是组合：**

> I use **inheritance** when there is a clear “is-a” relationship and **a stable shared contract**.
> I use **composition** when rules can change independently.
> In EasyAccess, I used **a shared request** flow with service-specific steps.
> If more rule types change independently, I would consider separate strategies.

**SOLID：**不要背五个字母后停住。挑两个说清：

> I keep business rules separate from database code.
> I depend on a small contract so that I can replace an external service in tests.

Liskov 追问：替换实现不能偷偷改变缺失值、异常或副作用等契约。

## Q8. Explain polymorphism and a virtual function.

> **Polymorphism** means that **one contract can have different implementations**.
> For example, two supplier clients can implement the same interface.
> The caller uses the interface and does not need to know the **concrete** class.
> In C#, a **virtual method** has a **base implementation** that a **derived class can override**.
> The method called at runtime depends on the actual object.

**追问：virtual / abstract / new？**

> A **virtual method** has an implementation. An **abstract method** requires an implementation in a concrete derived class.
> The new keyword hides a member. It does not have the same behavior as override.

C# 普通类方法默认非 virtual；接口派发与接口默认成员另有规则。不要套用“Java普通实例方法通常可重写”到 C#。可运行例子见12配套代码。[微软 virtual](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/virtual)

## Q9. Create an algorithm to find the largest common factor of two numbers.

通常是 GCD / greatest common divisor（最大公约数），先确认不是要求列出所有共同因子。

> Do you mean the greatest common divisor?
> I would use the Euclidean algorithm.
> I replace the pair with the second number and the remainder, until the second number is zero.
> The remaining number is the answer.
> I would also confirm how to handle negative numbers and two zeros.

例如 `(48,18) → (18,12) → (12,6) → (6,0)`，答案6。练习采用非负结果，`GCD(0,0)=0` 是约定，不是必须采用的数学定义。输入是 int，转 long 后取绝对值，避免 `int.MinValue` 溢出。时间 O(log max(|a|,|b|))，额外空间 O(1)。虽然主练非算法题，这道小题也留作备用。

## Q10. What is stable sorting?

> A stable sort **keeps the original order of items** with equal keys.
> For example, if Alice and Bob have the same score and Alice comes first, she stays first after sorting by score.
> This is useful when the original order has meaning.
> Stability does not make an undefined database order reliable. For that, I would add a clear tie-breaker.

示例：`(A,2),(B,1),(C,2)` 按数值稳定排序后是 `B,A,C`。Java有序流的`Stream.sorted`保证等key保留原有顺序，无序流没有这一保证。[Oracle Stream文档](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/stream/Stream.html#sorted(java.util.Comparator))。LINQ to Objects `Enumerable.OrderBy` 文档保证稳定排序；`List<T>.Sort` 没有这一保证。SQL结果想要稳定分页，应显式写唯一决胜字段如 `ORDER BY StartAt, Id`；不能依赖某次执行的物理顺序。[微软 OrderBy](https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.orderby)

## Q16. What are DICOM tags?

> DICOM is **a standard for medical images and related information**.
> A tag identifies a data element using a group number and an element number.
> For example, Patient ID is (0010,0020).
> The value representation describes the value type.
> I would use a DICOM library and check the required fields for the specific object type.

| Tag | 名称 | 面试用途 |
|---|---|---|
| (0010,0010) | Patient's Name | 不能仅靠姓名匹配患者 |
| (0010,0020) | Patient ID | 与机构/标识命名空间一起解释 |
| (0008,0060) | Modality | 对象的检查/设备类型信息，如 CT |
| (0020,000D) | Study Instance UID | 检查标识 |
| (0020,000E) | Series Instance UID | 序列标识 |
| (0008,0016) | SOP Class UID | 对象类别 |
| (0008,0018) | SOP Instance UID | 具体对象实例 |
| (7FE0,0010) | Pixel Data | 像素数据；不能假定每类对象都含它 |

**追问：Patient ID globally unique?**

> I would not assume that. I would check the issuer and the source system.

**追问：Missing tag?**

> I would check whether the field is required for that object. I would reject or hold an invalid object with a clear reason, instead of guessing a value.

DICOM不是“带几个字段的JPEG”；常见复合影像层级 Patient → Study → Series → Instance，一个实例也可多帧。字段要求看 IOD：Type1要求有效值，Type2要求存在但可空，Type3可选；还可能有条件要求。Tag、VR、字段必须性不是同一概念。依据：[NEMA数据集编码](https://dicom.nema.org/medical/dicom/current/output/chtml/part05/chapter_7.html)；本轮另读取[NEMA标签字典](https://dicom.nema.org/medical/dicom/current/output/chtml/part06/chapter_6.html)核对了表中8个标签；字段要求见既有[官方来源专题](医疗信息化标准与临床系统/05-官方来源与事实边界.md)。
