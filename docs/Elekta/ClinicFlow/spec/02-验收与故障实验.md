# 验收与故障实验

## 1. 验收矩阵

| ID | 场景 | 可检查结果 |
|---|---|---|
| A01 | 从干净检出按README启动 | 数据迁移与虚构种子数据成功；前后端和数据库可用，演示账号能登录 |
| A02 | 创建连续多个时段的预约 | 一个预约占满正确时段，审计和Outbox同时产生 |
| A03 | 两个独立客户端并发争抢相同资源时段 | 只有一个成功，另一个得到业务冲突；数据库无双占用 |
| A04 | 多时段中某个时段已占用 | 创建失败，没有残留预约、部分占用、成功幂等记录或Outbox |
| A05 | 改期目标冲突或事务中故障 | 原预约时间/状态/版本/占用完整保留，无虚假审计成功 |
| A06 | 改期目标与自身旧时段部分重叠 | 合法改期成功，仅保留新占用；状态与任务按规则重置 |
| A07 | 跨资源改期与相反方向并发改期 | 不违反占用约束；异常可解释，有界处理且不永久卡住 |
| A08 | 同版本并发修改预约 | 一个修改成功，旧版本请求被拒绝，不静默覆盖 |
| A09 | 任务未完成就确认；取消后继续操作 | 非法转换被服务端拒绝；完成当前前置任务后才可确认 |
| A10 | 同Key同负载顺序/并发请求 | 仅一个业务效果，重放取得相同结果；异负载同Key明确冲突 |
| A11 | 本地成功但响应丢失后重试 | 不再创建/修改一次，能够获取原结果 |
| A12 | 取消与重复取消 | 占用释放一次，审计不因幂等重放重复写入；后续可重新预约 |
| A13 | 外部服务停机再恢复 | 本地预约可查询，同步显示失败/待重试；恢复后最终同步 |
| A14 | 外部已保存但响应丢失 | 重试不重复产生对应效果，接收端重启后仍能去重 |
| A15 | 同对象旧版本在新版本之后送达 | 外部最终状态保持最新版本，旧消息不能复活已取消预约 |
| A16 | 工作进程领取后中断/两个工作者并行 | 租约过期可恢复，旧领取者不能错误覆盖新领取状态 |
| A17 | 达到重试上限/管理员重试 | 进入明确失败状态；手动重试保留消息身份和历史 |
| A18 | 未登录/无权限调用每类写接口 | 分别拒绝，不能绕过前端操作服务端 |
| A19 | 查询列表、详情、时间边界 | 排序稳定、分页与过滤正确、UTC与显示时区一致、相邻时段不冲突 |
| A20 | FHIR映射与契约 | 选定版本的支持字段正确；无效输入可解释拒绝；限制有文档 |
| A21 | UI完整流程 | 创建→完成任务→确认→改期→取消可演示；冲突与同步故障可见 |
| A22 | 从旧schema升级到新schema | 保留原样例数据；迁移记录、备份恢复演练与适用条件可查 |
| A23 | CI与交付 | 后端/前端构建和相关测试通过；每个功能有commit与push记录 |

并发测试必须使用独立连接/客户端和受控同步点，检验最终数据库状态，不仅比较HTTP响应。失败注入用可控屏障或配置，避免依赖碰巧的线程时序。每个ID映射实际测试名或手动验收记录；未执行要标“未执行”和原因。

## 2. 测试结构

- 单测：状态转换、时段拆分、任务前置、版本比较、重试计划和请求规范化。
- 集成测试：真实MySQL上的唯一约束、事务回滚、并发修改、幂等、租约和审计；隔离测试数据库，测试结束清理。
- HTTP契约：模拟服务成功、超时、永久失败、重复和乱序，以及FHIR映射。
- 浏览器流程：至少完成一次A21，并检查权限和409反馈；前端构建与类型检查必须通过。
- 测试构建通过后，不反复全量运行没有新增价值的检查；提交前按影响范围运行，里程碑做完整验收。

## 3. 三个故障实验

实验与正常应用隔离，必须显式启用并使用独立数据库/Compose配置或独立实验程序。正常启动不包含缺陷行为。数据只用生成的虚构数据。

### L1 并发覆盖

提供刻意移除Version检查的实验实现，两个客户端读取同一版本后分别修改。用同步屏障稳定触发最后写入覆盖，提供操作步骤和观察点。练习任务是补版本条件并明确冲突响应；验收对应A08。正常实现保留正确行为，实验不靠手动编辑生产路径开关。

### L2 重复外部处理

实验接收端关闭持久去重，并注入“保存成功后断开响应”。观察重试造成重复副作用计数。练习恢复持久MessageId去重及原子写入，验收对应A14；同时解释状态覆盖式PUT可能天然幂等，但关联事件/通知仍可能重复。

### L3 慢查询

生成可配置规模的预约数据，提供缺索引或不合理查询的实验版本。记录固定数据量、参数、机器环境、执行计划和计时，比较修复前后。练习索引或查询调整，并测试结果集合、排序与分页语义保持一致。不预设提升百分比，不把笔记本实验当生产收益。

每个实验交付：启动/复现/重置命令、现象、日志/SQL线索、待验证假设、验收条件。答案保存在单独解析文档，正常阅读路线不提前展开。

## 4. 质量和升级材料

提供需求ID→设计→代码→测试的轻量对应表、一份RCA报告、一份缺陷修复与影响分析、一份数据库升级检查清单。至少实际演练一次保留样例数据的schema变更；区分应用回退与数据库恢复，破坏性迁移不能声称切回旧程序即可恢复。
