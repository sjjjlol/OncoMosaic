# 学习与面试材料

## 1. 组织原则

用户熟练Java，C#/.NET作为迁移学习。按一条真实业务请求组织材料：浏览器操作→API→业务规则→数据库事务→Outbox→外部服务→前端状态。每章指向实际代码文件/符号，解释为什么需要、如何验证以及对应Java/Spring概念；实现改变后同步链接。

重点解释C#类型系统、可空类型、异常、集合/LINQ、async/await与CancellationToken、IDisposable、ASP.NET中间件/DI作用域、EF Core跟踪与迁移、后台服务与作用域、配置/日志/测试。不要把.NET等价成“换语法的Spring”。

## 2. 必交文档

- README：英文项目介绍、实际版本、启动/停止/重置、演示账号配置方式、测试命令、功能与限制。附中文快速开始。
- 架构与数据模型：模块依赖图、ER图、创建/改期/同步时序图，以及实际事务边界。
- Java开发者阅读路线：按文件导航的关键链路；解释与Spring事务、线程池、JPA等的异同，避免不准确一对一类比。
- ADR：至少记录时段模型、锁协议、幂等、Outbox/版本防倒退、认证及数据访问版本选择；说明替代方案与取舍。
- 接口说明：OpenAPI与错误码、权限、幂等/版本条件、FHIR支持范围。
- 故障练习：每个实验一份任务说明，解析与修复证据单独放置。
- 质量材料：需求/测试对应表、RCA、升级检查记录；英文缺陷更新和PR描述样例标注为练习。
- 演示与面试：3分钟演示、90秒项目介绍、并发/事务/异步/重试/测试追问及边界；技术依据来自实际实现。
- 进度文档：功能、验证、Git交付状态、待办；供新会话续接。

## 3. 七天学习路线

| 天 | 学习与操作 | 个人验收产物 |
|---|---|---|
| D1 | 启动、UI体验、C#基础与项目结构 | 画出创建预约的实际调用链 |
| D2 | API、DI、ORM、SQL和权限 | 修改一个查询条件，解释SQL与权限检查 |
| D3 | 多时段事务、改期、版本和幂等 | 运行竞争实验，用时间线解释唯一约束与锁职责 |
| D4 | async/await、后台服务、Outbox | 演示外部断网恢复和响应丢失，解释结果未知 |
| D5 | 自动化测试、RCA、查询性能 | 独立提交一份有证据的故障分析 |
| D6 | 独立需求实现、测试与代码审查 | 一笔自己完成的功能提交与失败路径测试 |
| D7 | 升级验证、FHIR入门、英文与面试 | 3分钟演示＋90秒中英文介绍＋技术追问 |

可压缩为五天，合并D1/D2及D6/D7，但保留亲手修改、故障复现和讲述练习。

## 4. 用户独立任务

默认任务：增加“预约完成Completed”状态。用户自己确定合法前置状态、完成后的占用与历史查询语义，补后端规则、权限、审计/Outbox、前端按钮和测试，并在评审中解释与取消的区别。开发助手在初版中不提前实现或交付完整答案，只提供需求问题、相关代码入口和验收骨架。

若初版设计变化使此任务不适合，可换成同等规模的真实状态/规则扩展，并在任务文档说明选择。它需要涉及业务判断与测试，不能仅改配色或字段标签。

## 5. 项目经历表述

该项目是针对面试的学习实践，不是Elekta产品或已上线医疗软件。初版由AI协助搭建，用户通过阅读、实验与独立修改掌握；讲稿分别标明已理解、已亲自实现和仅设计的内容。性能数字只取可复现本机实验，解释环境和数据规模，不能包装为企业生产指标。
