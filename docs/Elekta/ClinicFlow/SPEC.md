> 本目录归档独立练习项目的设计资料；文中的状态与时间属于当时记录，不表示 OncoMosaic 的实现进度。此处不包含 ClinicFlow 应用源码。

状态：方案已确认，待新会话开发。记录日期：2026-09-23。

## 1. 目标与交付方式

为Elekta MOSAIQ软件开发岗位准备一个可运行、可学习、可演示的C#/.NET项目。用户熟练Java并有企业系统开发经验，计划用5–7天、每天3–4小时学习。由开发助手先交付运行版本和文档，用户随后阅读、修改、完成一个独立需求并接受代码追问。

用户已确认：React＋TypeScript前端、ASP.NET Core后端、MySQL、模块化单体；以模拟诊疗资源预约为主线；覆盖业务设计、并发排障、测试、外部API、质量文档和英语表达；允许隔离的故障实验。项目应有系统设计深度，复杂性集中在事务一致性、并发和外部同步。

**交付约定：每完成一个功能切片，验证后独立commit并push到用户指定GitHub仓库。** 具体规则见[开发与Git交付](spec/03-开发与Git交付.md)。本次仅沉淀spec，未开始实现、安装依赖或创建远程仓库。

## 3. 功能范围

- 模拟患者、预约资源、资源时段查询。
- 创建预约、连续多时段占用、改期、取消、详情和分页列表。
- 前置任务检查与确认预约；三种预置角色和服务端权限控制。
- 业务版本冲突检测、请求幂等、事务性审计。
- Outbox与后台同步、模拟外部服务、受控重试及人工重新触发。
- 一个明确声明版本和资源范围的FHIR小型接口练习。
- 正常应用＋三个隔离故障实验＋自动化测试＋CI＋升级检查记录。
- 中文学习材料、Java/Spring对照、英文README/缺陷报告/PR示例。

边界：使用虚构患者和资源；不做剂量计算、治疗方案、设备控制或真实医院接入。主线不引入消息队列、微服务平台、完整DICOM/HL7 v2协议栈、注册找回密码或企业SSO。完整FHIR兼容与医疗产品认证不属于本项目声明。

## 4. 技术基线与待核验项

- ASP.NET Core Web API；优先选择受支持的.NET LTS与兼容数据库提供程序。具体SDK、ORM和驱动版本在M0核验并固定，不能只按“最新版”拼装。
- 数据访问优先EF Core；锁与性能问题允许局部参数化SQL，文档解释取舍。
- React＋TypeScript；前端做完整简洁的业务页面，提供加载、空态、错误、冲突和同步失败反馈。
- MySQL，真实关系数据库集成测试；内存数据库不能替代事务与锁行为验证。
- 数据库与模拟服务优先Docker Compose；后端支持本地调试；最终提供清晰的一键运行路径。
- 测试工具由开发者选择并记录：.NET单测/集成测试、前端检查和关键流程浏览器测试。
- GitHub Actions做构建与测试，CD体现为可重复构建的制品/容器和本地交付；不默认部署公网或付费云。

2026-09-23只读环境核查：macOS Apple Silicon；Docker CLI/daemon与Node/npm可用；PATH未找到dotnet。新会话重新核实环境，按需安装SDK或使用容器，明确实际运行方式。SQL Server对照放入文档，不将双数据库运行列为验收要求。

## 5. 完成定义

功能完成以[验收矩阵](spec/02-验收与故障实验.md)为准：正常链路和关键失败路径通过；学习材料与实际代码一致；故障实验可复现且与正常版本隔离；所有切片均有独立提交和远程push证据。代码已生成、进程启动或提交成功，均不能独自代表项目完成。
