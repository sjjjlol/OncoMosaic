# 四层模块化单体，先保证单实例的正确性

本项目的首要目标是长期维护与学习生产级 .NET 的设计方法，同时便于多人协作。采用 Domain、Application、Infrastructure、Api 四个程序集，在编译期约束依赖方向；暂不采用微服务或消息队列，因为当前业务规模和部署需求不足以抵消其运维、一致性与故障排查成本。

后台分析在一个 API 实例中的一个 worker 上执行，数据库保存队列和尝试次数，API 与 Python 共用文件卷。启动恢复依赖“前一个 worker 已停止”的前提，因此数据库行锁并不意味着本系统已经支持多实例；多实例演进必须另行设计租约、心跳、执行代次和分布式存储。
