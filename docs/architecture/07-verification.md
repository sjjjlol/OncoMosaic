## 验证中处理的环境问题

原有 .NET 10.0.100 ARM 容器在依赖还原阶段出现 `Illegal instruction`。仅关闭硬件指令优化未解决；加入串行还原后构建成功。最终 Dockerfile 保留硬件指令关闭和 `--disable-parallel` 的组合，原有 SVE 关闭也保留。这个验证证明组合配置可用，没有把它夸大为已经定位到某条 JIT 指令。它可能影响性能，未来升级运行时后应重新评估并做基准测试。

完整 Compose 重建还遇到 Docker Hub TLS 握手超时，随后单独构建当前 API 镜像并启动已有的前端、推理镜像完成回归；本轮未修改前端和 Python 源码，它们另有本机测试及构建验证。

本机缺少当前 Playwright 版本指定的 Chromium，因此最终使用仓库默认 Chrome 通道运行，3 项通过。CI 仍安装 Chromium 再测试。本地成功不等于已经观察到远端 CI 成功，远端流水线尚未在本会话中触发。

## 仍然存在的限制

ImageSharp 3.1.12 的已知依赖告警未解决。升级到当前修复版本涉及许可证和 Release 构建要求，本轮没有擅自引入许可证，也没有隐藏告警。两个加密传递依赖已显式升级，测试通过。发布前应完成依赖处置并收紧 NuGet 警告例外。

系统仍然无认证、无可信操作者身份、无多实例调度、无文件对账自动化或容量测试。有关边界和后续开发顺序见 [测试与运行](05-testing-operations.md) 和 [扩展练习](06-evolution.md)。这些限制与本轮事先确定的范围一致，不能把四层结构当作“已满足所有生产上线条件”的证明。
