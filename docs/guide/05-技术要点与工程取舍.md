# 05 工程取舍、验证层次与升级路径

[返回手册](../PROJECT_GUIDE.md) · [上一章](04-实现原理与流程图.md) · [下一章](06-面试话术与追问.md)

平台能成功运行、数字能复算、医学结论可信，是三个不同层次。本章解释当前取舍，以及未来替换真实数据或模型时应补哪些证据。

贯穿验证的研究目标见[第 00 章](00-项目背景与研究故事.md)：用固定四标记面板描述上皮与 T 细胞候选对象的组成和空间关系。交付优先级应围绕这个问题制定，让读者知道每项工程工作最终保护哪一个数字。

## 理想平台的主要设计取舍

面试时，取舍要说明具体约束、选择理由和代价，而不是简单列技术名词。以下是面向目标平台的决策框架，后面再说明当前工程范围。

| 决策 | 建议的起点 | 何时需要调整 |
|---|---|---|
| 分析模块怎样划分 | 以质控、组织、对象、测量和统计等可检查产物划分 | 经独立验证的联合模型能更好满足需求时，可合并计算，保留评价能力 |
| 同步还是异步 | 导入元数据等短请求同步，图像分析异步 | 更大规模时增加调度、资源配额与任务优先级 |
| 小视野还是整切片 | 先验证局部视野完整流程 | 研究要求全切片覆盖时增加瓦片、坐标与边缘对象处理 |
| 存全部数据还是只存汇总 | 保存原始输入及足以复核的定量、对象和版本数据 | 根据重算成本与保存要求制定分层存储策略 |
| 自动分类还是人工确认 | 自动产生结果，问题区域和不确定对象进入复核 | 按用途、性能与风险制定可自动确认的条件 |
| 一套通用模型还是按场景区分 | 明确支持的面板、组织与采集条件 | 扩展前取得新条件下的独立验证，避免仅凭同格式就接收 |

### 改变配置时，如何保持科学解释一致

配置不只是技术参数，还包括对象定义、纳入区域、强度尺度、表型规则和空间距离定义。这些改变可能使前后结果不再可直接比较，因此应形成新方案版本，并在报告中保留。

例如将密度分母从全部组织改为肿瘤相关区域，即使对象计数一样，也回答了不同问题。版本号只能记录变化，平台还应告诉用户变化的业务含义。

### 怎样设计性能目标

先约定典型图像大小、波段数量、并发任务数和硬件条件，再测量导入、预览、推理、发布和导出耗时。分别观察单任务延迟与整体吞吐，不用一个“速度提升”概括全部情况。

优先优化实际瓶颈。读取慢可考虑布局和缓存，推理慢再考虑批处理或计算资源；对象量大时评估查询分页和空间索引。任何优化都应检查是否改变精度、坐标或统计语义。

### 怎样设计可靠性目标

至少覆盖重复提交、计算中断、写盘失败、数据库发布失败和服务重启。系统应给出明确状态，能解释重试结果，并避免重复对象或半成品报告。

多人编辑还要处理版本冲突；批量任务要让单个失败可定位、可重试，而不是整批结果只有一个模糊的成功标志。

### 建议的交付阶段

1. **定义与数据阶段：** 确定面板、对象、区域和统计定义，建立输入及参考标注规则。
2. **完整流程阶段：** 跑通图像到对象、复核及导出，验证版本、单位和失败恢复。
3. **真实算法阶段：** 使用独立真实数据评价各模块与最终指标，明确适用范围。
4. **规模与协作阶段：** 根据需求扩展整切片、多用户、批量处理和资源调度。

每个阶段都需要可检查产物。更复杂的架构不能替代算法证据，更高的模型指标也不能替代可追溯的产品流程。

## 1. 当前选择的理由和代价

| 选择 | 解决的问题 | 仍需承担的限制 |
|---|---|---|
| OME-TIFF＋assay 伴随文件 | 用图像格式保存多波段像素，另存实验与参考谱说明 | 只支持受限的单视野结构；不是任意扫描仪文件即插即用 |
| 固定四标记面板 | 能明确展示核定位、上皮候选与 T 细胞候选的关系 | 无法覆盖全部细胞种类或肿瘤类型；新增标记要改契约与验证 |
| 独立合成真值 | 可知道生成场景的答案，避免推理直接读取答案 | 数学场景简单，不能代表真实病理难度 |
| 确定性参考分析器 | 便于解释、调试及复现每一步 | 没有学习真实组织形态；固定阈值难以跨批次适用 |
| 核加近似测量区 | 在缺少全细胞边界证据时仍能演示逐对象测量 | 相邻信号可能混入，不能声称精确全细胞表达量 |
| 有效组织面积作分母 | 避免机械地把矩形内空白也算作组织 | 当前掩膜只是阈值规则，仍可能把应保留或应排除的像素分错 |
| 浮点测量和人工版本分别保存 | 能区分原始测量、自动规则与人工修改 | 不保存完整浮点标记图，不能只靠导出包重做任意像素分析 |
| 持久任务与原子发布 | 重试时减少重复和半成品结果 | 当前部署面向单机、单 worker；没有完成大规模调度方案 |

## 2. 四种“通过”分别能证明什么

### 2.1 文件契约通过

证明文件满足当前代码要求，例如尺寸正确、波长数量匹配、哈希一致。不能证明图像是正确的实验对象，不能证明试剂特异，也不能证明声明的单位和校准过程真实可靠。

例如把一套错误参考谱写进合法 JSON，只要数学检查通过，系统仍可能继续分析。防止这种错误需要实验资料审核及独立对照，而不只是更严格的 JSON schema。

### 2.2 工程测试通过

证明指定输入下程序按预期完成行为，例如越界 ROI 被拒绝、同一任务重试不重复、单位换算公式正确、人工版本可回看、CSV 与页面口径一致。

当前 [验收记录](../VERIFICATION.md)属于这一层。测试数量、浏览器截图和任务成功状态不能转换成医学敏感度、特异度或诊断准确率。

### 2.3 图像分析性能通过

需要真实且有代表性的图像、独立参考标注、预先定义的评价规则。应分别检查组织、核、测量和表型，不能只展示几张“看起来不错”的叠加图。

假如模型漏掉一半的弱阳性对象，却正确处理了强阳性对象，平均信号图可能很好看，密度仍会明显偏差。若两个核合并成一个，像素重叠指标可能尚可，逐对象计数却已错误。因此像素级与对象级评价要配合研究目的。[SITC 图像分析建议](https://jitc.bmj.com/content/13/1/e008875)

当前没有完成这一层的真实数据验证。

### 2.4 医学用途成立

即使对象计数准确，也不能自然推导“某个患者会对治疗响应”。这需要明确临床问题、适用人群、终点与相应研究证据。当前项目没有建立计数或空间距离与诊断、预后、治疗决策之间的有效关系。

## 3. 从模拟系统走向真实科研的合理顺序

### 第一步：明确研究问题和分析单位

先确定研究的组织类型、哪些区域纳入、采用什么对象定义、哪些比较有意义。还要明确统计独立单位：同一患者切出的多个视野并不是多个独立患者。不能把大量相似图块当作同等数量的独立病例，夸大样本量。

### 第二步：整理可追溯的数据包

保留原图、染色方案、试剂信息、采集设置、单染/未染及生物学对照、扫描批次和参考标注。明确参考谱怎么取得、是否同设备同条件，强度怎样校准。当前 assay 可保存部分信息，但不等于完整实验档案系统。

### 第三步：逐模块建立参考答案

组织区由适当的专业人员定义；核实例需标出边界、漏检和粘连；表型标签需有一致规则与无法判定选项。记录分歧及仲裁方式，不能把一个人的所有点击都当作无误差真值。

### 第四步：用独立数据评估

按病例及相关批次划分开发与测试数据，避免同一切片的相似块泄漏到不同集合。根据预定使用范围覆盖组织、染色强弱、设备或批次变化。除总体指标外，还要观察弱信号、密集区、裁剪边缘等困难情况。

这些步骤适用于规则算法，也适用于深度学习。是否用了神经网络不会取消对实验、标注和测试设计的要求。

### 第五步：保留结果语义并替换实现

真实模型可以输出更好的核实例、组织掩膜或对象表型，但接口仍应明确单位、坐标、区域定义、版本和质量状态。如果改成全细胞测量、增加新标记或引入分类概率，应升级数据契约，不能把含义不同的数值塞进旧字段而不说明。

### 第六步：持续检查新批次

上线到真实科研流程后，仍需核查新批次是否偏离已验证条件。不能因为模型文件没改，就认为输出质量也没变。染色、曝光、制片等上游变化都可能改变输入分布。

## 双 ROI 比较已交付到哪一步

当前已补齐同图像两个 ROI 的描述性对照，并将指标、类别、距离分布与原图对象/最近邻连线连接起来。它帮助研究者解释“这个数字来自哪些对象”，并通过固定复核版本保证导出一致。Python 仍使用模拟实现，尚未建立真实分析性能证据。

比较会检查模型/统计版本与阈值，并提示重叠区域。当前仍需使用者确定合理的取样方案；方案一致不等于两区域代表整个病例，也不自动消除染色、分割或 ROI 边缘偏差。跨病例层次、研究组统计、批量任务和多人版本冲突仍是后续平台建设。

工程验收覆盖最近邻 ID/坐标、等距选择、排除重算、历史不变、空目标、方案提醒、固定版本 CSV/JSON 及浏览器筛选联动。见[验收记录](../VERIFICATION.md)与[比较机器报告](../comparison-verification.json)。

## 4. 目前最重要的欠缺

以下是当前实现边界，不是已承诺完成的功能：

- 真实实验对照、参考谱提取和跨批次校准流程；
- 经验证的组织分区，以及可编辑组织掩膜的复核；
- 粘连核拆分、漏检补录、完整细胞边界及其参考标注；
- 每类表型的真实数据性能与不确定性评估；
- 完整浮点结果保留与更丰富的像素级复算；
- 整切片瓦片、多设备导入、跨视野空间坐标与边缘处理；
- 面向实际多人研究的权限与完整数据治理。

升级优先级应由研究问题决定。例如要准确报告密度，首先需要可靠的组织面积与对象计数；加入更多界面图表无法弥补这两项的偏差。

### 现有四标记故事应优先补强什么

| 希望可靠回答的问题 | 优先建设或验证的能力 |
|---|---|
| 同一个对象是否 CD3⁺CD8⁺？ | 参考光谱与串色控制、核/对象分割、信号归属和表型参考标注 |
| 有多少对象，每单位面积有多少？ | 漏检与粘连处理、有效组织掩膜、固定纳入规则和类别复核 |
| 两类对象有多近？ | 对象坐标、物理尺度、起点/目标定义、ROI 边缘处理 |
| 能否称为肿瘤细胞或肿瘤区域？ | 适用于目标组织的专业病理确认及独立验证 |
| 不同区域或样本能否比较？ | 一致的取样方案、染色与采集校准、病例层次和版本记录 |

新增标记需要研究问题、染色和对照、参考光谱、结果字段、分类规则及验证一起扩展。对当前阶段而言，先把这些基础能力做可靠，才能让四标记面板支持可信的真实科研结果。

## Ki-67 的交付与验证计划（目标）

按 [Ki-67 功能设计](../Ki67功能设计.md) 分阶段交付：先实现局部 ROI 的五标记输入、核内测量、独立状态、按群统计、复核和导出，再增加热点、几何复核及多 ROI 汇总。当前验收记录不证明这些能力已实现。

工程验收重点是核内/核外信号分离、缺失不补零、身份与状态独立、分母及覆盖率、标记级质量失败、版本回放和页面导出一致。新增合成数据应有独立 Ki-67 真值与对照，并保留旧面板回归。真实研究还需评价核分割、阳性判断及最终指数误差，按病例和批次独立验证；不能将模拟算术正确当作临床评分性能。

**Ki-67 交付状态：** 首期 ROI 模拟功能已实现，实际操作、字段与限制见 [Ki-67 实施说明](../Ki67实施说明.md)。本文中的热点、完整几何复核及真实医学验证仍为目标设计。
