# 06 面试话术与追问

[返回手册](../PROJECT_GUIDE.md) · [上一章：技术取舍](05-技术要点与工程取舍.md)

下面的话术以仓库已经实现、已经验证的能力为基础。使用前请按真实参与情况选择“我负责”“我参与”或“我复现并理解”，并补充你实际完成的部分。代码使用了 AI 辅助时，应如实说明如何定义规格、验证实现与处理问题；不要把这里的模板直接当成个人经历证明。

## 1. 30 秒开场

> OncoMosaic 是一个多标记组织图像定量分析的本地工程原型，使用 React、.NET 10、MySQL 和独立 Python 服务。用户可以导入图像、圈选 ROI、提交后台分析、查看核对象、人工复核并导出带方法记录的结果。我重点关注的是跨语言分析流程的可靠性，包括持久任务、重试幂等、坐标对齐和复核版本。当前数据和算法都是模拟的，没有宣称医学诊断准确率。

开场要让面试官知道三件事：做什么、你讨论的工程难点是什么、能力边界在哪里。不要一开始就连续罗列十几个框架名。

## 2. 两分钟项目介绍

> 这个项目围绕组织图像分析的一条完整流程展开。输入是一个带空间和波段维度的 NPZ 数据立方体，用户在网页上圈选感兴趣区域，系统返回核检测对象以及 DAPI、panCK、CD8 的模拟强度，再做分类和区域统计。
>
> 架构上，React 负责查看器和操作，ASP.NET Core 负责业务状态、数据库、统计、复核和导出，Python 负责数组与图像处理。MySQL 存测量和版本，图像与掩膜放在共享文件卷。浏览器只访问 API，不直接访问 Python。
>
> 第一个重点是后台任务。API 写入 Queued 状态后立即返回 202，由 BackgroundService 调用 Python。任务状态和 attempt 都持久化，失败后能重试，服务重启会恢复中断任务。为避免重复结果，我使用同一个 runId、Python 产物复用、原子目录发布，以及数据库事务和唯一约束。
>
> 第二个重点是结果可追溯。原始强度不被人工修改；复核使用追加版本，页面和导出明确绑定 runId 与 reviewVersion。导出中的 method.json 记录原图校验值、ROI、阈值、模型与复核信息。
>
> 验收包括契约测试、后端公式测试、浏览器操作和真实停服务重试。一个固定 ROI 检测出 69 个核，复核排除后有效数为 68，原始版本仍可导出。这里验证的是工程流程，不是医学准确率。

如果你只负责前端，把两段“重点”替换为坐标变换、统一 SVG 图层、异步请求代次与实际 UI 验证；如果只负责后端，不要暗示自己训练了图像模型。

## 4. 核心追问与回答

### Q1：Python 为什么不直接提供全部后端接口？

> Python 完全可以承担业务后端。本项目的选择是让 .NET 集中管理任务、规则、复核和数据库，把 Python 约束成图像处理适配器，便于以后替换计算实现。收益是职责边界清楚，代价是要维护跨语言契约、部署和故障处理。我不会仅凭语言名称宣称性能更高。

**源码证据：** [InferenceClient](../../backend/OncoMosaic.Api/Storage.cs)、[SpectralAdapter](../../inference/app/model.py)。

### Q2：异步任务为什么能在刷新后保留？

> 任务先写入 MySQL，浏览器持有的只是 runId。后台从数据库读取 Queued 记录执行，前端轮询状态。刷新后重新查询图像的任务列表，不依赖前端定时器保存业务真相。当前浏览器轮询周期是 1.2 秒，worker 空闲时每秒检查一次。

**不要说：** “用了 async/await，所以任务自动可靠。”异步语法本身不提供持久化。

### Q3：重试怎样保证不重复？

> 重试保留 runId，Python 检查同 run 的输入校验值、ROI 和模型版本，已有完整产物就复用。API 验证返回内容后，用数据库事务替换该 run 的结果；runId 与 localIndex 有唯一约束。我们还测试了关闭 Python 后失败、恢复后 attempt=2 成功且细胞数未翻倍。

**进一步限定：** 这是单实例幂等重放，不是跨多节点的 exactly-once。Python 互斥锁也是进程内的。

### Q4：API 写数据库时崩溃怎么办？文件怎么办？

> 数据库内的细胞、产物索引和成功状态在同一个事务中，提交前失败会回滚。Python 文件先用临时目录写完再重命名，因此不会正常返回半份 manifest。两者之间没有分布式事务，仍可能留下已发布但没有数据库引用的文件；同 run 重试可以复用，通用孤立文件清理是后续要补的治理能力。

这比回答“事务保证所有东西都原子”更准确。

### Q5：多个 API 实例能同时跑吗？

> 当前不能直接按多实例安全队列使用。worker 查询最早的 Queued 行再更新，尚未建立原子领取和租约；启动恢复逻辑也假设只有一个 worker。扩展时应设计领取锁或条件更新、租约过期、心跳和重试归属，并用并发测试验证。也可以考虑消息队列，但仍然需要幂等消费。

### Q6：为什么用 MySQL，不把所有数据放文件？

> 项目、图像、任务、细胞和复核之间存在明确关系，需要条件查询、唯一约束与事务。大数组和图像则保留在文件卷中，通过受控键与数据库关联。MySQL 是这次项目明确选定的数据库；重点是如何使用关系约束保证流程正确，而不是宣称它在所有场景优于其他数据库。

### Q7：缩放后 ROI 为什么不漂移？

> 持久化的坐标始终是原图像素坐标。鼠标位置先减去 SVG 的窗口偏移，再逆平移和逆缩放。图像、ROI 和细胞都在同一个 SVG group 里变换；Python 处理 ROI 后把偏移加回细胞中心和轮廓。这样前后端讨论的是同一个坐标系。

**可以板书：** `x=(screenX-tx)/scale`，再说明 `screenX` 是查看器局部坐标。

### Q8：为什么通道亮度不会改变阳性数？

> 原始浮点强度存入 Cells，PNG 只是 8 位显示图，透明度与颜色只是浏览器设置。.NET 分类和统计直接使用保存的强度，因此切换显示不会重算医学量。修改阳性阈值则是业务规则变化，会创建一个新的分析 run。

### Q9：人工复核怎么保留历史？

> 不直接更新原始强度，而是追加 ReviewRevision 和 ReviewChange。读取某版本时先计算自动标签，再按版本顺序应用人工覆盖。同一细胞反复修改，以指定版本以内最后一次修改为准。版本分配使用事务内的任务行锁，数据库也有唯一索引。

**追问：这是不是事件溯源？** 可以说具有追加式修正记录的思想，但没有构建完整事件溯源基础设施，也没有用户身份审计。

### Q10：导出为什么和页面一致？

> 页面导出传入当前显示的具体复核版本。服务端先组装同一个 Snapshot，再生成 CSV、PNG 和方法 JSON，统计调用同一份 Quantification。PNG 是按该版本有效类别重绘，不是临时截图。我们检查了 CSV 行数、有效核数与 API 汇总，也验证了 v0 在后续复核后仍不变化。

### Q11：你实现了什么“AI 模型”？

> 首版没有训练深度学习模型。mock-unmix-v1 是确定性的模拟适配器：固定波段分组均值生成三个通道，用 DAPI 阈值和连通区域得到核，再做区域平均强度测量。它的作用是验证真实服务调用、数据结构、交互和追溯流程。接真实模型要另做数据适配与医学验证。

### Q12：panCK 阳性为什么不能直接叫肿瘤细胞？

> panCK 是上皮相关标记，阳性本身不足以判断良恶性；本项目又是合成信号。因此只有 ROI 标为肿瘤候选区域时，界面才显示“候选肿瘤相关细胞”。CD8 信号也不能单独确认某种 T 细胞身份。更准确的解释和来源在医学概念章节。

### Q13：距离为 0 是错误吗？为什么有时显示“无可计算对象”？

> 不一定。当前定义允许双阳性对象在目标集合中匹配自身，因此可以得到 0；如果 CD8 或 panCK 阳性集合为空，则没有可计算配对，返回 null。0 是有效数值，null 是缺失语义，混用会误导分析。

### Q14：排除一个细胞后，比例和密度为什么不同步变化？

> 比例分母是有效核数，密度分母是 ROI 面积。例如排除一个 CD8 阴性核，CD8 阳性数不变、有效核数下降，所以比例上升；面积和阳性数都不变，密度就不变。浏览器实例里 CD8 比例从 29.5% 变为 30.0%，密度仍约为 3069/mm²。

### Q15：大图和很多细胞时的瓶颈是什么？

> 当前 SVG 展示全部对象，最近邻是两组对象的双层遍历，Python 核周测量会重复构造 ROI 尺寸的掩膜，导出也在内存里生成。更大规模应评估瓦片、Canvas/WebGL、空间索引、KD-tree、局部包围盒测量和流式导出。现有项目没有做完整压力测试，所以不会给出未经测量的性能提升数字。

### Q16：算法升级后能复现旧结果吗？

> 当前输入、测量、阈值和复核记录可追溯，也记录模型/算法版本，但仅有版本字段不等于完整历史执行环境。自动标签仍由当前后端代码根据旧阈值推导。真正升级分类算法时，需要按版本保留旧实现或固化旧自动结果，并记录代码/依赖/模型产物身份，才能加强跨版本复现。

## 5. 用 STAR 组织一个技术难点

下面是基于当前仓库的讲解示例，不是虚构的线上事故经历。

**S（背景）：** 图像分析由外部 Python 服务执行，耗时与失败不受浏览器控制；用户可能刷新页面、重试任务或修改类别。

**T（目标）：** 任务和结果能够持续保存，重试不重复入库，人工修改可回看，导出能够解释其来源。

**A（行动）：** 把任务状态写入 MySQL；采用 worker 调用 Python；建立 manifest 和坐标/掩膜校验；通过原子文件发布、事务和唯一约束控制重复结果；把复核设计为追加版本；导出使用明确的版本快照。

**R（结果）：** 在固定演示 ROI 上得到 69 个核，排除后有效数为 68；关闭 Python 产生失败，恢复后第二次执行成功且仍为 69 个核；数据库/API 重启后历史复核和导出保留。结果说明的是工程验收通过，不是临床识别性能。

## 6. 简历描述模板

根据实际参与范围选择或改写，不要直接把所有条目都当作个人贡献：

- 参与/实现 React + ASP.NET Core + MySQL + Python 的多标记组织图像分析原型，贯通 NPZ 导入、ROI、模拟分析、复核和可追溯导出。
- 设计/实现持久任务状态和幂等结果发布，通过输入指纹、事务与唯一约束控制失败重试，验证服务故障和重启恢复。
- 实现/维护统一原图坐标查看器及版本化复核，保留原始测量；按任务与复核版本生成一致的 CSV、PNG 和方法记录。
- 完成/复现契约、公式和浏览器端到端验收，区分工程流程验证与医学性能验证。

不填写没有证据的“准确率 99%”“支持百万级细胞”“吞吐提升 10 倍”“已用于医院生产”等数字或经历。

## 7. 面试前十分钟自检

你应当能够脱离稿件解释：

1. 一次点击“开始分析”经过了哪些进程和表。
2. 为什么需要原图坐标，Python ROI 偏移在哪里加回。
3. 检测阈值和分类阈值分别控制什么。
4. 比例、密度和距离的分母/单位是什么。
5. 重试与多实例并发是两个不同问题。
6. 原始测量、自动标签、有效标签和复核版本的关系。
7. 文件原子发布与数据库事务之间仍有什么边界。
8. 现有模拟算法做了什么、没有做什么。
9. 哪些实际测试能支持自己的说法。
10. 哪些代码是自己写的、哪些借助工具完成、自己如何验证。
